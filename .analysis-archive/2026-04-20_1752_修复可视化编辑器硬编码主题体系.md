<analysis>
context:
  1. `src/presentation/pages/visualizer-styles.ts` 顶部第14-50行直接在 `#acu-visualizer-content` 上**硬编码**了一整套 `--vis-*` 变量默认值：
     - 暗色默认：`#24221f`, `#36332e`, `#c1b9ad`, `#7d4940` 等
     - 浅色特例：`body.acu-theme-silk #acu-visualizer-content { ... }`
     这意味着就算主题系统把 `--acu-*` 变量正确注入到 visualizer 根节点，visualizer UI 仍然优先吃自己内部那套写死的 `--vis-*` 默认值。
  2. `visualizer-styles.ts` 后续几乎所有组件都依赖 `--vis-*` 变量，而不是直接使用 `--acu-*`。因此 visualizer 的主题切换是否生效，关键根本不在 `--acu-*` 是否注入，而在于 `--vis-*` 是否正确映射到当前主题变量。
  3. 当前样式文件只对“素纱主题”做了一个特例选择器：
     - `body.acu-theme-silk #acu-visualizer-content { ... }`
     这说明 visualizer 现在本质上是“默认写死一套墨韵暗色 + 对某个主题手写例外”，而不是接入统一主题系统。这个设计不是不优雅，是根本不合格。新增一个主题就要继续往这里塞一坨特判，维护性接近零。
  4. grep 结果显示 visualizer-styles.ts 内还有大量直接写死的色值，不只是顶部变量定义，还有：
     - `.acu-table-nav-item.active { background: rgba(125, 73, 64, 0.10); }`
     - `.acu-table-order-btn:hover { background: rgba(125, 73, 64, 0.12); }`
     - `.acu-btn-primary { background: rgba(125, 73, 64, 0.12); }`
     - `.acu-btn-primary:hover { background: rgba(125, 73, 64, 0.18); }`
     这些值与“墨韵清雅”主题强绑定，就算把 `--vis-accent` 改掉，仍会残留旧主题色调。
  5. `visualizer.ts` 第92-117行确认编辑器 HTML 内部直接插入 `<style>${VISUALIZER_CSS_ACU}</style>`。这意味着 visualizer 自己的样式定义紧贴在内容内部，且大部分变量/色值由这份样式文件控制。
  6. 之前修复的 `theme-registry.ts` 选择器错误只是修了“注入打不中节点”的问题，但真正让 UI 仍然“不跟随”的主因，是 visualizer CSS 自己内部就把主题写死了。
  7. 正确方向不是继续为每个主题写 `body.acu-theme-xxx` 特判，而是：
     - 让 `--vis-*` 默认映射到 `--acu-*`
     - 把那些写死的 rgba/hex 改成基于 `--vis-*` / `--acu-*` 的变量表达
     - 把“素纱主题”这种特殊 case 移除，统一纳入主题变量体系

needs:

  2. 去掉 visualizer-styles.ts 中与特定主题耦合的硬编码色值，尤其是与墨韵主题绑定的 rgba 背景。
  3. 保持 visualizer 自有设计语言（例如 `--vis-*` 变量层）但让它成为 `--acu-*` 的语义映射层，而不是一套独立固定皮肤。
  4. 删除 `body.acu-theme-silk` 这种特判路径，避免未来每加一个主题就继续堆分支。

approach:
  采用“保留 `--vis-*` 作为语义层，但全面改成映射 `--acu-*`”的方案。
  1. 修改 `visualizer-styles.ts` 顶部变量定义：
     - 删除“默认暗色写死值 + 素纱主题特判”
     - 改为 `--vis-*` 默认映射到 `--acu-*`，例如：
       - `--vis-bg-color: var(--acu-viz-bg, var(--acu-bg-0))`
       - `--vis-border-color: var(--acu-viz-border, var(--acu-border))`
       - `--vis-text-main: var(--acu-viz-text, var(--acu-text-1))`
       - `--vis-accent: var(--acu-viz-accent, var(--acu-accent))`
       - 等等
  2. 将关键写死背景色改成变量表达：
     - 所有 `rgba(125, 73, 64, ...)` 这类与墨韵主题绑定的值，替换为基于 `--vis-accent` / `--vis-accent-glow` / `--vis-bg-light` 的变量组合
     - checkbox 勾选图标如果仍写死白色，评估是否保留；若背景色由 accent 控制且需要高对比，可暂保留白色勾，但要优先改背景体系
  3. 保留 visualizer 的布局、字体和组件层级，不做无关重构，只修颜色系统。
  4. 既然 `theme-registry.ts` 已经能向 visualizer 根作用域注入核心变量和 `visualizerVariables`，这次修完样式层之后，主题切换就会真正贯通。

  - 主题 accent 很浅时，按钮 hover / active 背景不能完全不可见，变量表达应保留足够对比度
  - 删除 `body.acu-theme-silk` 后，古典浅色主题必须仍然能通过 `--acu-*` / `--acu-viz-*` 映射得到接近原先风格
  - 直接写死的 `rgba(125, 73, 64, ...)` 至少要覆盖 active nav、排序按钮 hover、primary button 背景等高频视觉节点，否则仍然会残留旧主题味道
  - 不能误改 layout / spacing / responsive 区域，避免把颜色修复变成视觉回归
