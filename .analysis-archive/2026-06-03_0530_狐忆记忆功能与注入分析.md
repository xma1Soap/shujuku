# 狐忆.txt 记忆功能 + 记忆注入功能技术分析

## §0 一句话定性

狐忆.txt 的“记忆”是 localStorage 里的一个持久化结构（每角色卡独立存储），系统通过**两条独立链路**使用它：

- **写入端**：自动/手动分析完成 → LLM 解析聊天上下文 → 生成/修正/删除记忆条目 → 写回 localStorage。
- **读取端**：拦截用户输入后润色时（占位符动态注入）+ 预设条目常驻注入（整库序列化）→ 把记忆喂回 LLM。

两条链路不共享中间状态、不互斥、可能同时启用。

## §1 记忆数据模型与持久化

### 1.1 持久化键

代码使用 localStorage 作为唯一存储后端（未发现 IndexedDB/Dexie 痕迹）：

| 键名 | 隔离粒度 | 代码位置 |
|---|---|---|
| `SPreset_FoxMemory_${encodeURIComponent(charId)}` | 每角色卡 | 狐忆.txt:5896, 5916 |
| `SPreset_FoxMemoryConfig` | 全局共享 | 狐忆.txt:5931, 5979 |

字符 ID 走 `encodeURIComponent` 转义，理论上能覆盖角色卡 ID 含特殊字符的场景。**上下文不足**：`getCurrentCharId` 的实现位置未在本轮已读区段（推断在 5800 之前的初始化区段）。

## §3 读取端 1：拦截链路中的记忆注入（占位符动态注入）

### 3.1 拦截入口

- `registerFoxPushListener`（狐忆.txt:3701-3739）在 capture 阶段钩 `#send_but` click 与 `#send_textarea` Enter。
- 点击/回车后 `foxPushInterceptAndPolish`（@3609-3696）执行 `stopImmediatePropagation + preventDefault`（@3634-3636），阻止酒馆原生发送。
- 调用 `foxPushGenerate` 完成润色与重发。

### 3.2 占位符机制（核心思想）

**目的**：避免把整个记忆库塞进 prompt，让 LLM 在润色输出中"按需引用"记忆 ID。

#### 3.2.1 占位符构建

`foxMemoryBuildPlaceholders`（狐忆.txt:3477-3491）：
- 输入：当前记忆列表 `memories`。
- 输出：模块级变量 `foxMemoryPlaceholders`（@3472）—— `Array<{tag: '<memoryNNNN>', text: '完整记忆文本'}>`。
- 索引格式：`<memory0000>`、`<memory0001>`……四位补零。
- 同时构造 `promptIndexText`（@3482-3488）喂给 LLM 当作"可用资料目录"。

**关键点**：占位符文本被嵌入到 `foxPushGenerate` 构造的 systemPrompt 的"可用资料"段中（@3516-3528）。

#### 3.2.2 LLM 输出格式约束

润色 prompt 要求 LLM 在 `【当前需要回忆的内容】` 段中**只写占位符标签**（如 `<memory0003>`），不要展开。

#### 3.2.3 占位符替换

`foxMemoryReplacePlaceholders(text)`（狐忆.txt:3496-3503）：
- 对 `text` 内的每个占位符 `tag` 执行 `text.replaceAll(tag, entry.text)`。
- **无 escape 机制**：若 LLM 输出意外出现 `<memory0000>`（如用户文本拼接、上下文脏数据），会被当作合法占位符替换。

#### 3.2.4 上下文数据源合并

`foxPushGenerate`（@3508-3598）合并 3 个上下文：

| 数据源 | 函数 | 代码位置 |
|---|---|---|
| 最近 N 楼 | `foxMemoryGetRecallContext` | 狐忆.txt:3511, 2951-2964 |
| 当前记忆库 | `foxMemoryGetCurrent` | 狐忆.txt:3512 |
| 狐搜上下文（可选） | `foxMemoryGetHusouContext` | 狐忆.txt:3513, 2976-2991 |

合并后注入 systemPrompt 的"可用资料"段 → 调用 `getFn('generateRaw')` → 解析 LLM 输出 → `foxMemoryReplacePlaceholders` 替换 → 回填 `ta.value` → 重发（@3653-3672）。

### 3.3 记忆库为空时行为

`foxPushGenerate` 若 `foxMemoryGetCurrent` 返回空（@3512），注入 `'（当前记忆库为空）'` 提示（@3479），**仍调用 LLM**——降级到"无记忆可用"模式，**非短路跳过**。

### 3.4 重试与状态机

- `__foxPushRetryScheduled`（@3730）：自动重试标志。
- `foxPushStartHandle` / `foxPushIsProcessing` / `foxPushSkipNext`（@3416-3418）：拦截链路状态机。
- `foxPushSkipNext` 标志让酒馆原生事件在下一次重发时**放行**（@3658-3662 推测），避免无限循环拦截。


## §4 读取端 2：预设条目常驻注入（整库序列化）

### 4.1 目标预设条目

`foxMemorySyncToPreset`（狐忆.txt:2156-2192）将整库记忆序列化后写入酒馆预设条目：

- **目标 ID**：`a765deed-a057-436a-9239-a7863f87460a`（**硬编码 UUID**）。
- 写入 API：`getPreset('in_use')` 获取当前预设 → `setPromptContentById(targetId, text)` → `togglePromptById(targetId, true)`。
- 文本格式：`【🦊狐忆长期记忆库】` + 拼接每条记忆的 `类别标签 + 标题 + 时间 + 内容 + 关键词`。

### 4.2 关闭入口

`foxMemoryDisablePresetInject`（狐忆.txt:2194-2198）：仅做 `togglePromptById(targetId, false)`，**不删除文本**——文本仍在条目中，关闭只是不送入 prompt。

### 4.3 启用条件

- `foxMemoryConfig.injectToPreset`（推断在 openFoxMemoryPanel @2200-2680 的"基础配置"section 渲染）。
- 调用触发：面板"基础配置"section 的同步按钮（推断，@2200-2680 范围内）。

### 4.4 与占位符注入的关系

- **两条链路在代码中无显式互斥逻辑**。
- 可能同时启用：占位符动态注入（拦截阶段）+ 预设常驻注入（每次生成）。
- 后果：**token 重复消耗**（同一记忆在 LLM 输入中出现两次：一次作为预设条目，一次作为占位符候选）。

## §5 上下文过滤系统（写入端读取上下文前的预处理）

### 5.1 目的

把聊天中的"被排除段"（不想让记忆分析看到的内容）剥离，再喂给 `foxMemoryCallApi` 做 LLM 分析。

### 5.2 核心函数

#### 5.2.1 `foxMemoryFilterContent(text, config)`（狐忆.txt:2846-2904）

输入：原文 + 过滤配置（includeTagStarts/Ends/excludeTagStarts/Ends）。
流程：
1. 解析 `enableContentFilter` 开关（@2852）。
2. `include` 优先：`foxMemoryFindExactRanges`（@2766-2828）按配对标签定位区间 → 区间外内容丢弃。
3. include 未匹配 → 回退到 `foxMemoryApplyExcludeToChunk`（@2830-2844），即"扣掉 exclude 范围"的全文本。
4. exclude 模式：直接 `foxMemoryApplyExcludeToChunk`。
5. 标签未配置或全空 → 返回原文。

#### 5.2.2 `foxMemoryFindExactRanges(text, startTag, endTag)`（@2766-2828）

- 配对模式：`[startTag...endTag]` 整体保留。
- 仅开始模式：标签后到末尾全部保留。
- 仅结束模式：开头到标签前全部保留。
- 区间合并：`foxMemoryMergeRanges`（@2727-2748）—— 按 start 排序后线性扫描，区间重叠或相邻则合并。
- 区间移除：`foxMemoryRemoveRanges`（@2750-2764）—— 排除被保留区间以外的部分（include）或被排除区间（exclude）。

#### 5.2.3 过滤模式汇总

| 模式 | 行为 | 触发条件 |
|---|---|---|
| include + 完整配对 | 只取标签内 | `includeTagStarts && includeTagEnds` 都配 |
| include + 仅开始 | 标签后全部 | 仅 starts 配，ends 留空 |
| include + 仅结束 | 标签前全部 | 仅 ends 配，starts 留空 |
| include 配对失败 | 回退到扣 exclude | starts/ends 不匹配 |
| exclude + 任意 | 扣 exclude 段 | 任意一端配 |
| 无标签 | 原文返回 | starts/ends 全空 |

### 5.3 上游数据源

| 函数 | 返回 | 代码位置 | 用途 |
|---|---|---|---|
| `foxMemoryGetFullContext('all')` | 整个 chat（`getChatMessages(range, {hide_state: 'unhidden'})`） | 狐忆.txt:2906-2945 | 完整分析场景 |
| `foxMemoryGetRecentContext()` | 最近 N 楼 | 狐忆.txt:2947-2949 | 轻量分析 |
| `foxMemoryGetRecallContext()` | 最近 `recallFloors` 楼 | 狐忆.txt:2951-2964 | 拦截链路喂入 LLM |
| `foxMemoryGetAllAsText()` | 全库记忆拼接 | 狐忆.txt:2966-2974 | 上下文注入 |
| `foxMemoryGetHusouContext()` | 狐搜上下文 | 狐忆.txt:2976-2991 | 拦截链路可选启用 |

### 5.4 纯字符串操作

整套过滤是**字符串 indexOf + 切片**，无语法解析，无 AST，无 token 化。优势是**零依赖、零失败**；代价是：
- 嵌套标签无法识别。
- 标签跨行需要配置里写完整字符串。
- 标签如果出现在用户内容中（极小概率），会误识别。


## §6 风险点（按风险等级排序）

### 6.1 [高] localStorage 容量硬上限

- **函数**：`saveFoxMemory`（狐忆.txt:5914-5924）+ `saveFoxMemoryConfig`（@5977-5985）。
- **触发条件**：单条记忆内容 > 1KB 或记忆总数 > 1000 条 → 单角色卡 SPreset_FoxMemory_${charId} 键可能突破 localStorage 5MB 上限，setItem 抛 QuotaExceededError。
- **后果**：写入失败，记忆丢失；脚本未捕获异常，可能导致 UI 静默异常。
- **代码证据**：未发现 try/catch 包绕 setItem，也未发现容量预警或分片逻辑。

### 6.2 [高] 硬编码 UUID 跨角色卡不通用

- **函数**：`foxMemorySyncToPreset`（@2156-2192）+ `foxMemoryDisablePresetInject`（@2194-2198）。
- **触发条件**：新角色卡没有预设条目 `a765deed-a057-436a-9239-a7863f87460a` → setPromptContentById/togglePromptById 调用酒馆内部会失败或创建新条目，**没有 fallback 探测**。
- **后果**：预设常驻注入链路在部分角色卡上完全失效；用户不查日志不会发现。
- **代码证据**：脚本依赖酒馆侧"每个角色卡都有这个 UUID 的预设条目"；本工作区无法验证假设（酒馆版本/预设模板可能不一致）。

### 6.3 [高] 占位符无 escape 机制

- **函数**：`foxMemoryReplacePlaceholders`（@3496-3503）。
- **触发条件**：LLM 输出中意外出现 `<memory0000>` 字面量（用户文本拼接、上下文脏数据、LLM 不遵守 prompt 约束）→ `replaceAll(tag, text)` 会把无关内容当作记忆文本替换进去。
- **后果**：润色结果中出现大段无关记忆内容，且无法追溯（无日志）。
- **代码证据**：无 escape、无 hash 校验、无原文长度白名单。

### 6.4 [中] 拦截链路中无记忆库存在性短路

- **函数**：`foxPushGenerate`（@3508-3598）。
- **触发条件**：`foxMemoryGetCurrent` 返回空数组（@3512）。
- **当前行为**：注入 `'（当前记忆库为空）'` 提示（@3479），**仍调用 LLM**。
- **后果**：用户每次发送消息都付一次额外的 LLM 调用费，**没有短路跳过**。
- **改进方向**：记忆库为空时直接放行原文本，不调 LLM。

### 6.5 [中] 模块级变量并发风险

- **函数**：`foxMemoryPlaceholders`（@3472，模块级 let）。
- **触发条件**：未来若扩展为多 capture 拦截（不止 `#send_but` click）或异步并发触发 `foxPushGenerate`。
- **当前安全性**：单 capture + 单线程 JS 下安全——`foxPushStartHandle` / `foxPushIsProcessing` 状态机已防重入。
- **后果**：模式上不鲁棒，重构时易踩坑。
- **代码证据**：未发现锁/队列机制，仅靠 `foxPushIsProcessing` 标志防重入。

### 6.6 [中] GENERATION_ENDED 1000ms 延迟

- **函数**：`foxMemoryAutoHandle`（@3446-3450）。
- **触发条件**：用户在同一秒内连续发 2 次消息（被剧情推进 5s 去重阻止的可能性高，但分析链路无去重）。
- **后果**：第二个分析可能读到未完全入库的 chat 状态；分析结果可能重复或丢失。
- **代码证据**：`setTimeout(1000)` 硬编码，无重入检测。

### 6.7 [中] 预设注入 vs 占位符注入无显式互斥

- **函数**：`foxMemorySyncToPreset`（@2156-2192） + `foxPushGenerate`（@3508-3598）。
- **触发条件**：用户同时启用 `injectToPreset=true` + `autoPush=true`（占位符拦截）。
- **后果**：同一记忆在 LLM 输入中出现两次（一次作为预设条目 `a765deed...` 段，一次作为占位符候选 `<memoryNNNN>`），**token 重复消耗**。
- **代码证据**：未发现互斥检查，未发现用户提示。

### 6.8 [低] localStorage 同步阻塞

- **函数**：`saveFoxMemory`（@5914-5924）+ `saveFoxMemoryConfig`（@5977-5985）。
- **触发条件**：记忆库大（> 1MB）时保存。
- **后果**：保存期间 UI 卡顿（setItem 同步阻塞主线程），但不影响功能正确性。
- **代码证据**：未发现 requestIdleCallback / setTimeout(0) 异步化。

## §7 复用可能性判断

### 7.1 可借鉴的设计思想

| 设计点 | 借鉴价值 | 借鉴方式 |
|---|---|---|
| **占位符机制**（@3477-3503） | 高 | 拦截+润色场景下，**避免把整个数据库塞进 prompt**，让 LLM 按需引用 ID；可改造为"剧情要素库"占位符 |
| **标签字符串过滤**（@2846-2904） | 中 | 纯字符串 indexOf + 切片，**零依赖、零失败**；适合"章节过滤 / OOC 过滤 / 私聊过滤"等场景 |
| **per-char 隔离持久化**（@5896, 5916） | 中 | `SPreset_<Plugin>_${encodeURIComponent(charId)}` 命名约定清晰；本工作区可参照 |
| **autoMode 三态分发**（@3434-3464） | 中 | auto / interval / manual 三态门控明确，UI 配置项清晰；可改造为"剧情推进触发模式" |
| **配置中心化**（loadFoxMemoryConfig @5929-5972） | 中 | 默认值 + 用户值合并策略简单可读；本工作区已有类似机制可参照 |
| **区间合并算法**（@2727-2748） | 低 | 排序 + 线性扫描；通用算法，不强依赖狐忆实现 |

### 7.2 不可直接借鉴的部分

| 风险点 | 不可借鉴原因 | 替代方案 |
|---|---|---|
| **DOM capture 拦截**（@3634-3636） | 油猴脚本依赖 `topDoc` / `topWindow`，本工作区插件模式无 topDoc | 走酒馆官方 API：`SillyTavern.getContext().getSendButton()` + 钩子替代 |
| **localStorage 持久化** | 本工作区油猴/插件双模下可能与酒馆扩展存储冲突 | 使用酒馆原生 `SillyTavern.getContext().extensionSettings` 或 IndexedDB |
| **硬编码 UUID**（`a765deed-...`） | 跨角色卡不通用 | 改为可配置：首次启用时探测/创建预设条目，存到插件配置 |
| **单文件 7903 行架构** | 无模块化、无 TypeScript、无测试覆盖 | 本工作区用 TypeScript 模块化 + tests/ 目录 |
| **GENERATION_ENDED 1000ms 延迟** | 硬编码延迟不鲁棒 | 用 `eventSource.on` + await 消息入库完成事件 |
| **同步 setItem** | UI 卡顿 | 改异步 + 容量预警 + 分片 |
| **占位符无 escape** | LLM 误输出会被替换 | 加 hash 校验 / 长度白名单 / escape 机制 |
| **预设/占位符无互斥** | token 重复消耗 | 显式互斥或合并 |
| **酒馆内置 API 同名同语义** | 本工作区无法直接验证 | 需先在 `src/shared/host-api.ts` 中确认是否包装了等效函数 |

### 7.3 复用路径建议

如要本工作区引入"长期记忆库"概念，建议路径：

1. **存储层**：用酒馆原生 extensionSettings（per-char 隔离），不用 localStorage。
2. **写入端**：复用 autoMode 三态思想，但用 eventSource + 消息入库事件替代 1000ms 硬编码延迟。
3. **读取端**：
   - 拦截+润色场景 → 借鉴占位符机制，但加 escape/校验。
   - 预设常驻注入 → 不直接借鉴硬编码 UUID，改首次启用时探测/创建。
4. **过滤**：借鉴标签字符串过滤，改造为支持"剧情要素标签" / "OOC 标签"。
5. **测试**：本工作区有 tests/ 目录，迁移时必须加单元测试覆盖（狐忆.txt 无测试）。
6. **模块化**：拆分为 `memory-store.ts` / `memory-analyzer.ts` / `memory-injector.ts` / `memory-filter.ts` 等模块，不要复制 7903 行单文件架构。
